# Labs

A public lab of small static web experiments, live at https://labs.eugeneyip.net. Do the technical work (installing, building, checking in the browser, committing) yourself rather than asking the owner to run terminal commands.

@FACTORY_CONSTITUTION.md

## Autonomous operation

Work runs across many sessions, and the repository holds its state, not any chat. Four files are authoritative: this one, `.claude/FACTORY_STATE.md` (its "Now" section first), `.claude/AUTONOMOUS_QUEUE.md`, and the current batch's checkpoint (named in "Now").

- **Resuming.** At the start of a session and after the context is compacted, a hook (`.claude/hooks/session-context.sh`) prints "Now", the batch checkpoint's "Now", and the state of git. If it didn't, read those yourself and run `git status` and `git branch`. Then continue from the recorded next action, before anything else and without waiting to be told. Never redo verified work.
- **Continuing.** Finishing a step, or a whole experiment, isn't a reason to stop while a batch is authorized: record it, checkpoint, and start the next step. Stop only when the batch is complete, when everything left needs the owner, at a safety or authorization boundary, or after repeated technical failures where another attempt is unlikely to help. When you stop, say which of these applies and leave "Now" saying exactly what comes next.
- **Asking the owner.** Only about something that changes what's authorized, costs money, needs credentials or an account, contacts anyone, or changes an outside account or setting. Settle everything technical yourself (implementation, tests, browser checks, research method, fixtures, fixes, documents, deploy checks), and never ask whether to continue. If the owner asks to pause, set **Autonomy** in "Now" to `paused`.
- **Blocked lanes.** Mark the lane BLOCKED — OWNER REQUIRED in `.claude/AUTONOMOUS_QUEUE.md`, park only that lane, and carry on with the rest.
- **Checkpoints.** Verified work never lives only in the chat or the working tree. An experiment under construction lives on a local branch, `wip/<number>-<slug>`, committed at each milestone and never pushed (its audit comes before any public push); it reaches `main` as one squashed commit when it ships. Other state updates (discovery, records) are committed to `main`, which must stay deployable. Update "Now" and the batch checkpoint at every milestone, so the next session can continue from them alone. Never rewrite pushed history.
- **Long jobs.** Bound every run and every wait inside a script. QA scripts run through `sh .claude/scripts/qa.sh <seconds> <script in .claude/qa/> [args]`, which stops the script's whole process group at the limit; anything else uses `perl -e 'alarm shift; exec @ARGV' <seconds> <command>` (macOS has no `timeout`). Write partial results to files as you go. Give each research thread or sub-agent one bounded purpose, and never wait on one indefinitely: if it stalls or hits a limit, keep what it found (its transcript counts), park that lane, and continue elsewhere. The main session owns continuation. Say whether a failure is the test harness's or the product's.
- **Permissions.** `.claude/settings.json` allows without asking: read-only git, builds, local commits, the WIP-branch lifecycle (`wip/*` only), `git push origin main`, the QA scripts and the bounded runner, the records (`.claude/*.md`, `.claude/batch-*/`, the Product Log), and web research. It refuses secrets, privilege escalation, force pushes, pushing `wip/` branches, deleting remote branches, and account or credential changes. Other pushes, installing packages, deleting files, and changing settings, hooks, scripts, or the constitution still go through the normal check. Never work around a refusal.
- **The Stop hook.** While **Autonomy** is `active`, `.claude/hooks/stop-continue.sh` turns a stop into a request to carry on with the next action. It lets the stop through when no tool was used since it last asked, or after 3 asks in 10 minutes, and logs each decision to `.claude/hooks/stop-hook.log`. Offline cases: `sh .claude/scripts/stop-hook-test.sh`.

## Quick reference

- `npm run dev`: local server on port 5173 (the "dev" entry in `.claude/launch.json`).
- `npm run build`: type-check and production build. Must pass before every push.
- Pushing to `main` deploys automatically through GitHub Actions.
- New experiment: `src/experiments/<slug>/index.tsx` plus an entry in `src/experiments/registry.ts` (including the homepage `category` it's listed under), then an entry in `PRODUCT_LOG.md`.
- Saving: an experiment that keeps work in localStorage saves through `useOtherTabs` (`src/components/useOtherTabs.ts`), so two open tabs don't erase each other's work, and shows `NotSaving` (`src/components/NotSaving.tsx`) when the browser refuses to save. A changed saved format goes under a new key, as the hook's comment explains.
- Offline support: `public/sw.js` keeps the site's own pages and files once opened, so experiments work without a connection. Online, pages are fetched first (the browser's own cache may answer for up to 10 minutes, GitHub Pages' `max-age`), and the saved copy is used if that takes over 4 seconds; outside services and personal data are never cached. It's registered only in the built site (`src/main.tsx`). To turn it off for everyone, publish a `sw.js` that deletes its caches and unregisters itself on activate.
