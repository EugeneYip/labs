# Security and privacy audit

P4 of the autonomous queue, 2026-10-11 and 2026-10-12, covering all 25 experiments and the homepage.

**What can go wrong on a static site.** Labs has no accounts, server, database, or analytics, so there's nothing to break into and nothing collected. What's left:
- hostile or huge content a visitor pastes or opens (ballots, PDF text, scripts, CSV files, photos);
- crafted share links someone sends them (Custody Calendar, Fair Share, Secret Santa);
- damaged saved data (an older version, a browser fault, a hand edit). It can break a page on every visit, because the same data loads each time;
- files made for other programs that misbehave when opened (CSV formulas, calendar files);
- data leaving the device without the visitor knowing (outside services, online speech voices);
- links to dangerous kinds of address (Trip Board).

**Not covered:**
- GitHub's and the domain registrar's own security;
- the visitor's device and browser extensions;
- network attackers, beyond the HTTPS setup (see the HSTS risk below);
- Safari and Firefox themselves: Brave's Chromium and Playwright's WebKit 27.2 were run (see `.claude/BROWSER_MATRIX.md`).

## Method

| Check | How | Scope |
|---|---|---|
| Code review | Raw HTML (`dangerouslySetInnerHTML`, `innerHTML`, `eval`), outside requests, every storage read, share-link decoders, exports, new-tab links, speech, clipboard, the service worker | All of `src/`, `index.html`, `public/sw.js` |
| Storage fuzz | `.claude/qa/p4-storage.cjs` with valid saved states from `p4-storage-seeds.cjs`. Every field (for lists, the first record) is replaced by each of 18 hostile values, and each key by each of 9 unreadable or oddly shaped strings. Each case loads the page, then reloads it. It fails on the load-failure message, a page error, or a polluted `Object.prototype`. A failing case runs once more; one that passes then is counted as flaky | The 21 experiments that save to localStorage: 4,863 cases |
| Edge times | `p4-edge-times.cjs`: saved times at, just inside, and just past the range a JavaScript date can show (±8.64e15 ms) | 10 time fields × 6 values, plus Serve Time's longest delays: 62 cases |

| Links | `p4-decoders.ts` | Trip Board: 18 dangerous kinds of address |
| CSV formulas | `p4-decoders.ts`, plus the existing Ranked Choice Count and Stall Till checks | All 4 CSV exports |

### Results of the fixes

- **Ranked Choice Count:** 25 model tests, including names like `__proto__`, `constructor`, and `toString` in instant runoff and STV, and punctuation, emoji, right-to-left text, and formula-looking names. The count matches the independent reference (`.claude/qa/rcc-reference/`) on 2,801 random elections, with 0 mismatches and 0 seat-count violations. In the built page, in both engines, `__proto__` wins by instant runoff (5 votes after Cleo's transfer) and is elected by STV, and the 30-million-ballot paste is refused in about 0.2 s.
- **Saved data:** a targeted fuzz of the five experiments above (1,769 cases) shows none of the 13 earlier failures; 9 one-off load failures there pass 3 times out of 3 on a rerun, each having failed on only one of its two loads of the same data. The 62 edge-time cases pass in both engines. Fluency Check with every write failing shows the alert and the honest button label in both engines, and the normal "Saved on this device" when writes work.
- **Clean Paste:** identical output to the old version on 4,045 inputs (10,520 comparisons across option settings) and 6 long documents (1.2 MB). The real-PDF check is unchanged (8 of 14 paragraphs exact, 0 word differences); 18 tests and 26 stress cases pass. In the built page, a 1 MB paste shows in 0.1 s in WebKit and 1 to 3 s in Chromium; a profile puts about 40 ms of that in Clean Paste and the rest in the browser's own text box (setting its value takes about 1 s).
- **Photo Scrub:** the old and new XMP reading give identical reports on 5,003 generated packets (attributes and elements, rdf lists, entities, duplicates, unclosed tags), and on 1,000 more with out-of-range references the old one threw 376 times and the new one never (`p4-photo-xmp-diff.ts`). The canary photos clean to byte-identical files with identical reports. 23 tests pass; the 2 new ones fail on the old code. In the built page, in both engines, both crafted photos are cleaned in about 0.1 s. (The canary check, `photo-canary/verify.py`, flags the orientation-only EXIF that Photo Scrub keeps on purpose; no canary text survives in any file.)
- **Off Book:** with an online default voice, en-US and en-AU get the device's David, en-GB gets Hazel, and fr-FR, with no voice on the device, is left to the browser, in both engines. The note shows only while reading aloud is on; no overflow at 320 px.

## Storage fuzz after the fixes

**Before the fixes** (`out/p4-storage-chromium.txt`): 4,863 cases in Chromium, 13 failures: Fluency Check 3, Stall Till 3, Fair Share 4, Serve Time 3, each the load-failure message on both loads.

**After the fixes:**
- **Chromium, all 21 experiments** (`out/p4-storage-chromium-2.txt`): 4,863 cases, **none of the 13 earlier failures, and no failure caused by saved data.** The local Python server dropped connections under the load of three test runs at once, so 37 cases failed twice and 363 once, every one with a `net::ERR_CONNECTION_RESET` or `ERR_SOCKET_NOT_CONNECTED` on one of the site's own files (even the favicon). Rerun one at a time without the server (`p4-storage-rerun.cjs` with `route-preload.cjs`, 3 times each), all 37 pass (`out/p4-storage-chromium-2-rerun.txt`). Three of them, in Gallery Wall, first failed again because the stand-in origin was plain `http://labs.local`, where browsers don't offer `crypto.randomUUID`; on `https://labs.local`, a secure context like production, they pass.
- **WebKit, all 21 experiments** (`out/p4-storage-webkit-full.txt`): 4,863 cases on `https://labs.local`, served from the built folder without a server: **0 failed, 0 flaky.** (A first full run crashed inside Playwright when its browser went away; the rerun, with 4 workers instead of 6, was clean. A targeted run of the five fixed experiments on plain `http://` was clean too.)
- **Edge times:** the 62 cases pass in both engines, after Serve Time's margin was added.

## Checked and sound

- **No raw HTML.** React escapes every piece of text it shows. The one `innerHTML` is the fixed start-failure message in `index.html`; there's no `eval`, `new Function`, or `document.write`. React 19 also refuses `javascript:` addresses in links.
- **Outside requests.** Only Frost Dates and Line Dry make any, to Open-Meteo: the place search text and a place rounded to two decimal places (about a kilometer). No keys. The browser's default referrer policy sends Open-Meteo only `https://labs.eugeneyip.net/`. No other page loads anything from another site: no fonts, scripts, analytics, maps, or images.
- **Share links.** Custody Calendar, Fair Share, and Secret Santa put their data after `#`, which browsers never send to a server, so GitHub Pages and link-preview services don't see it. Custody Calendar removes it from the address bar once read. In the browser (`p4-sharelinks-make.ts`, `p4-sharelinks-browser.cjs`), 174 links per engine, each opened as a fresh page: 120 damaged ones, prototype-pollution JSON, a 20,001-character link, broken `%` escapes, `<script>` and `<img onerror>` text, and for Fair Share a 64,810-character link that inflates to 50 MB. None showed the load-failure message, threw, polluted `Object.prototype`, or ran script, in Chromium or WebKit; the undamaged links showed their data. In Node (`p4-decoders.ts`), 3,017 Custody Calendar codes, 1,512 Fair Share links, and 3,016 Secret Santa tokens never throw; whatever decodes is a valid schedule, group, or match; and `Object.prototype` stays clean. The 50 MB bomb is refused in 68 ms, because decompression stops at 1 MB.
- **Links.** Trip Board accepts only `http` and `https` addresses with a dotted host name and no user name or password, whether typed, pasted, loaded from storage, or imported from a file. All 18 dangerous forms are refused: `javascript:` in any case, after a space, or split by a tab or newline; `javascript&colon;`; full-width letters; `data:`, `file:`, `blob:`, and `vbscript:`; a protocol-relative `//`; a user name and password; `localhost`; spaces; an empty host; `http:/`; and a 3,000-character host.
- **CSV formulas.** All four exports (Fluency Check, Discussion Map, Ranked Choice Count, Stall Till) put an apostrophe before text starting with `=`, `+`, `-`, `@`, a tab, or a carriage return, then quote it if needed, as OWASP recommends; numbers stay numbers. Fluency Check removes the apostrophe again when it reads its own CSV back. CSV Checkup only reads files, and counts formula-like text for the visitor. Seven payloads (`=HYPERLINK(…)`, `+1+1`, `-2+3`, `@SUM(A1)`, a leading tab or carriage return, `=cmd|…`) come out with the apostrophe in the Fluency Check and Discussion Map exports; the same rule in Ranked Choice Count and Stall Till was checked in Batch 05 (plans rcc-5 and till-5).
- **New tabs.** Every `target="_blank"` link has `rel="noreferrer"` or `rel="noopener noreferrer"`.
- **Storage names.** Every key is `labs:<slug>` or `labs:<slug>:<name>`, and the one IndexedDB database is `labs:family-stories`, as the constitution requires.
- **Offline copies.** The service worker keeps only this site's own files and pages, never outside services' responses. Its saved copy of a page ignores the query and the `#` part, so share-link data never lands in the offline cache.
- **Random IDs.** Gallery Wall, Serve Time, and Photo Scrub call `crypto.randomUUID()` without a fallback (the other experiments check for it first). Browsers offer it only on secure pages; Labs is always served over HTTPS, and every supported browser has it (Safari 15.4, Chrome 92, Firefox 95), so it matters only on plain-`http` test addresses like the one above.
- **Feedback.** The feedback link opens a new GitHub issue with a note that it's public, so names and personal details should be left out. Labs itself collects nothing.
- **Secret Santa.** Each link is scrambled, not encrypted, and holds only that person's own match, so decoding one reveals nothing more. The organizer's device keeps the whole draw; the page asks them not to open other people's links.
- **Photo Scrub's other limits.** Data after a PNG's end is dropped from the clean copy. With the fix, 20 MB of ordinary XMP reads in 0.4 s, and 20 MB of character references in 0.7 s (3 s with other tests running).

## Residual risks, measured

| Risk | Measured | Why it stays, or where it goes next |
|---|---|---|
| **One storage budget for the whole site.** All 25 experiments share labs.eugeneyip.net's localStorage | 5,242,880 characters per site in both Chromium and WebKit (`p4-quota.cjs`). A Tear-Off Flyer photo, downscaled to 1,600 px and saved as a JPEG at 0.85, takes 53,000 to 1.5 million characters (smooth to detailed images), and up to 2.9 million for pure noise (`p4-photo-size.cjs`): up to 29% of the budget for a real photo. A Fluency Check check is about 200 to 400 characters | When it's full, 6 experiments say so (Fluency Check, Off Book, Stall Till, Tear-Off Flyer's photo, Trip Board, Family Stories). The other 16 that save (21 in localStorage, plus Family Stories; 15 was a miscount) do it silently, and the riskiest of those hold typed-in work: Ranked Choice Count's ballots, Discussion Map's session, Secret Santa's draw, Custody Calendar's schedule. **P9**: fixed for the 8 that hold work, and Tear-Off Flyer's text (`.claude/DURABILITY_AUDIT.md`) |
| **One damaged item hides a Trip Board.** Any unreadable item makes the whole saved board unreadable | The board is set aside under `labs:trip-board:unreadable` (nothing is lost), but the page shows an empty board with no message, so the visitor would think it was wiped. Stall Till, by contrast, says so and offers a download | **P9**: fixed (commit efd862d) |
| **Share links are bearer data.** Anyone with a Custody Calendar, Fair Share, or Secret Santa link sees what it holds, and a link can't be taken back | Inherent in links without accounts. Custody Calendar says so; the data never reaches a server | Stays; the wording covers it |
| **Online voices** where the device has none for the language (Off Book, Day Clock) | fr-FR with no device voice is left to the browser, which may use an online voice | Stays, and both pages say so. Numbers by Ear can prefer online voices, but it speaks only numbers it makes up, never what a visitor typed |
| **Open-Meteo** sees the visitor's IP address, what they type to find a place, and the place, rounded to about a kilometer | Limits are per IP address: about 120 Frost Dates lookups a day (earlier research) | Stays; both pages say what's sent |
| **No Content Security Policy.** GitHub Pages can't send headers, and a `<meta>` policy can't stop framing | No place where page content becomes HTML was found, so a policy would be defense in depth. In current browsers, a Labs page framed by another site gets separate, partitioned storage, not the visitor's saved data | Not added: no defect behind it, and it would need testing on all 26 pages (inline styles, the start-failure script, `blob:` and `data:` images). An option for the owner |
| **No HSTS.** GitHub Pages redirects `http://` to `https://` (301) but can't send `Strict-Transport-Security` for a custom domain | Checked on production with `curl -I`; responses carry `cache-control: max-age=600` and no security headers | On a hostile network, a first visit typed as `http://` could be intercepted before the redirect. Saved data stays safe, since it belongs to the `https://` origin, but a fake page could be shown. Fixing it needs HSTS preloading for eugeneyip.net, a domain-level decision for the owner |
| **Large inputs still take time** | Ranked Choice Count at its limit: a 13 MB Google Forms export of 100,000 rows parses in 1.2 s and counts in 0.3 s; 150,000 rows parse in 2.1 s, then are refused (`p4-rcc-large.ts`). Clean Paste in Chromium: 1 to 3 s for a 1 MB paste, almost all of it the browser's own text box. Photo Scrub: 20 MB of character references in one photo's XMP, 0.7 s | Linear, and bounded by each page's limits |
| **Off Book on one enormous line.** Finding speakers in a line full of unclosed `(` grows with the square of the line's length | A 500 KB script pasted as a single line, with an unclosed `(` every 80 characters, takes 16 s, and again on each visit once saved. A real script of 3,000 lines takes 75 ms; 2,000 lines of 200 `(` each, 0.3 s (`p4-offbook-bench.ts`) | Only the visitor's own paste can do it, and only without line breaks. **P13 candidate:** skip speaker patterns on lines too long to be a name |
| **Firefox** | Not run: it can't start inside the command sandbox (P3) | **BLOCKED — OWNER REQUIRED**, as in `.claude/BROWSER_MATRIX.md` |
